## 1. 产品定位

面向河北省石家庄市小学二、三年级学生的个人学习助理，覆盖语文、数学和英语。通过 iPad 原生 App、小动物虚拟导师、自然语音和视觉能力，帮助孩子管理作业、理解知识、完成练习，并持续维护有证据支持的知识掌握档案。

首版围绕放学后写作业展开，形成以下闭环：

作业录入 → 孩子完成与求助 → 检查订正 → 更新知识档案 → 针对性练习与复习 → 家长查看反馈。

核心价值：

- 根据真实学习表现了解孩子的知识基础和困难。
- 通过语音、视觉、虚拟形象和白板提供易用的互动体验。
- 提高独立完成和理解的程度，减少家长反复催促、重复讲题的负担。

## 3. 用户、角色与数据归属

### 3.1 家长

- 创建和管理孩子档案，设置年级、教材和学习目标。
- 添加、确认和修改作业，查看完成与订正进度。
- 查看知识点判断、依据、近期变化和需要协助的事项。
- 管理摄像头、麦克风权限及本地数据删除。
- 在同一台 iPad 上切换到家长界面查看记录。

### 3.2 孩子

- 通过头像和昵称选择自己的档案。
- 查看与补充作业，安排任务顺序，开始、暂停和结束学习。
- 通过语音、图片和白板获得帮助，完成订正与练习。
- 查看适合年龄的进步反馈，暂停音视频采集。

### 3.3 隔离规则

- 作业、回答、知识档案、复习任务和辅导记录均归属于具体孩子。
- 学习过程中明确显示当前孩子，避免误记到其他档案。
- 切换孩子时结束或暂停当前学习会话，重新加载对应上下文。
- 进入家长端使用 PIN 或系统身份验证，具体方案在交互设计中确定。
- “家庭账号”不意味着数据已同步到云端；首版登录与本地家庭身份的具体实现待技术设计确定。

## 4. 作业管理

### 4.1 录入

- 手动输入学科、作业内容和完成要求。
- 拍照识别作业要求，展示识别结果，确认后加入任务列表。
- 孩子可以补充作业，家长可以查看和修改。
- 识别不清或缺少信息时标记待确认，不将猜测当成作业要求。

### 4.2 状态

建议采用：待开始、进行中、需要帮助、待检查、待订正、已完成。

- 完成书写后进入检查，不直接推断知识已掌握。
- 检查发现问题后进入订正，订正完成后再次检查。
- 无法检查的任务明确标记，例如照片模糊、题目缺失或音频不清。
- 作业完成状态与知识掌握状态分别维护。

## 5. 辅导与主动介入

已确定的介入规则：

- 孩子求助时，结合当前语音、题目及可用画面回应。
- 孩子表示写好了后，检查答案和步骤，引导自查与订正。
- 较长时间没有进展时，轻声询问是否需要帮助；不直接判断为走神。
- 到约定休息时间时提醒休息。
- 书写过程中不逐笔纠错，保留独立思考和自查时间。

辅导顺序：询问思路 → 给提示 → 分步引导 → 必要时完整讲解 → 相似题验证。

- 孩子直接索要答案时，先给容易入手的提示。
- 确实不会时可以升级帮助，不重复追问导致受挫。
- 孩子打断时停止当前语音输出，处理新的问题。
- 无法确定题目或答案时，先确认材料，不能自信地编造题意和结论。
- 不使用羞辱、比较或失望表情催促学习。

## 6. 三科首版能力

| 学科 | 功能 |
| --- | --- |
| 数学 | 识别题目与手写步骤、分步辅导、订正、针对薄弱点生成相似题 |
| 语文 | 字词听写、朗读与背诵检查、课内阅读辅导、看图写话引导 |
| 英语 | 单词与句子听读、跟读反馈、听写、简单情境对话 |

语文写话先帮助孩子组织想法，再对孩子自己的表达给建议。听读和跟读评估应区分识别失败与学习错误；音频不清时允许重试，不据此降低掌握判断。

## 7. 知识档案与个性化练习

按年级、学科、教材版本、上下册和单元组织知识点；教材未确认时允许记录作业，但不强行映射到未经核实的教材单元。

每个知识点至少包含：

- 当前状态：尚未评估、学习中、初步掌握、掌握较稳、需要复习。
- 证据：相关作业或练习、回答、正确性、是否独立完成、提示程度、日期。
- 可能的困难与待验证判断。
- 推荐的后续练习或复习。

判断原则：

- 单次答对、照着讲解完成和孩子自称理解，都不足以单独证明掌握。
- 独立解释、相似题迁移和间隔后的表现提供进一步证据。
- 区分观察事实与推断，例如“使用了两次提示”和“可能不理解数量关系”。
- 识别失败、材料缺失和无法判定的结果不能当作答错。
- 采用可追溯的状态和说明，不先展示缺少校准依据的精确掌握百分比。

练习根据困难选择形式和难度，控制单次数量。效果关注独立完成、迁移和保持情况，而非仅统计使用时长。

## 8. 视觉、语音与虚拟导师

### 8.1 视觉

- 外接摄像头主要朝向课本和作业区域。
- 支持预览、拍照、检查清晰度及重新拍摄。
- 第一版以按需求助和完成后检查为主，不要求持续上传视频。
- 孩子说“这里”而定位不明确时，通过高亮、选择区域或追问确认。
- 需要验证近距离对焦、铅笔字、手部遮挡、整页覆盖与光线适应。

### 8.2 语音与形象

- 自然语音对话，可打断；提供字幕及必要的触控替代入口。
- 小动物导师与白板配合讲解，在安静学习时减少动作和打扰。
- 麦克风和摄像头状态明确可见，可以随时暂停。
- 首版建议采用 2D 形象、说话口型和倾听、思考、鼓励等基础动作。
- 具体动物、声音、命名与自定义范围留待视觉和交互设计。

## 9. 本地数据与服务端边界

本地保存孩子档案、作业图片、辅导记录、学习证据、知识状态和复习计划。默认不保存连续视频与原始录音，支持删除本地数据。

- 首版不做跨设备同步，也不提供家长手机远程查看。
- 不同设备上的记录独立；更换设备或卸载 App 存在数据丢失风险。
- 手动备份、恢复和系统备份策略需要单独确定，尚不算已确认功能。
- 使用云端模型时仅传输当前任务需要的内容；本地存储不代表完全离线。
- 自有服务端用于必要的鉴权、凭证和模型调用，不持久保存学习内容，日志避免记录学习内容。
- 长期供应商密钥不嵌入 App；模型供应商的数据保留与处理政策在选型时核实。
- 实时语音可评估短期凭证直连方案，具体路线通过延迟和成本测试确定。
- 网络中断时可访问本地已有任务和记录；智能辅导提示不可用并允许重试。

## 10. 首版技术边界

- iPad 原生 App；采用 SwiftUI，系统框架为 PhotosUI、AVFoundation、Speech、LocalAuthentication；手写交互可采用 PencilKit 或 SwiftUI Canvas。
- 以用户现有 iPad 为首个验收设备，记录型号与 iPadOS 版本。外接摄像头仅 USB-C iPad 且 iPadOS 17+ 可用，需验证识别、对焦与供电。
- Android 客户端（Kotlin + Jetpack Compose）保留，作为后续平台。
- 摄像头接入、语音打断、云端反馈和白板同步需要实机测试。
- 初期通过模型服务完成智能能力，不要求自行训练或部署大模型。
- 本地知识状态更新应有明确规则与证据，不完全依赖模型自由生成的结论。

## 11. 首版验证与验收

以下为验收场景；准确率、延迟和改善幅度的数值门槛待样例评测及试用基线后确定。

| 场景 | 验收关注点 |
| --- | --- |
| 家长添加两个孩子 | 档案、作业、会话和知识状态互不混淆 |
| 拍照导入作业 | 可核对修改，确认后才生成正式任务 |
| 孩子看题求助 | 能定位正确题目，必要时确认模糊内容，提供分级帮助 |
| 语音打断 | 能停止当前输出并接续孩子的问题 |
| 完成与订正 | 完成状态和掌握状态分别更新，订正有记录 |
| 相似题练习 | 不机械重复原题，结果能作为知识判断证据 |
| 多科辅导 | 使用按教材和年级整理的真实样例验证答案和反馈 |
| 摄像头不可用 | 支持自带摄像头拍照或手动输入求助 |
| 网络中断与 App 重启 | 本地已保存记录可恢复，不误标任务完成 |
| 数据删除 | 对应本地记录及其关联文件按选择范围删除 |
| 家长反馈 | 能看到具体进度、困难和判断依据，而非只有总分 |

试用同时观察孩子是否能独立操作、家长介入次数和耗时，以及孩子在新题与后续复习中的表现。首版不承诺提高考试分数。

## 12. 待确认项

1. 试点学校、三科教材版本、上下册与英语开课情况。
2. 可参与试用的孩子及真实作业样例。
3. 首发 iPad 型号、iPadOS 版本，以及是否需要外接摄像头。
4. 家庭账号登录、家长身份验证及恢复方式。
5. 本地数据保留期限、删除范围、手动备份及系统备份策略。
6. 小动物形象、声音，以及首版自定义程度。
7. 模型供应商、服务可用性、数据保留政策和单次使用成本预算。
8. 无进展询问与休息提醒的时机和频率。
9. 实机评测后的延迟、识别质量和辅导质量验收门槛。

上述事项不阻碍核心页面原型；教材内容验证、云端接入和硬件验收应在相关信息落实后完成。
