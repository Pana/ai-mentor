# 安卓一期：作业管理

起草：2026-11-13；状态更新：2026-11-24
对应需求：[一期需求：作业管理](./prd-phase1.md)；对应技术方案：[一期技术方案](./tech-plan-phase1.md)

安卓端实现了和 iOS 一期相同的作业管理流程，服务端接口不变，两端可以混用：例如家长用 iPhone、孩子用安卓平板，或家长用安卓手机、孩子用 iPad。

## 范围与取舍

| 事项 | 决定 |
| --- | --- |
| App | 沿用 `app/`（包名 `cn.littlebear.tutor`，可覆盖安装）。首次启动选“我是家长”或“这是孩子的设备”。旧版辅导代码保留在仓库里，但不再提供入口 |
| 设备与角色 | 按选择的角色区分，不按设备区分：家长端、孩子端在手机和平板上都能用。宽度 ≥ 600dp 时使用平板布局 |
| 奖励时间锁定 | 已实现无障碍服务拦截选定 App，奖励期间放行、到时重新锁定；需家长开启服务并选 App，小米设备还需自启动及省电“无限制”。iOS 仍只有记账和倒计时。详见[技术方案](tech-plan-phase1.md) |
| 推送 | 前台长轮询 `/v1/changes?wait=25`：另一台设备的改动 1 秒内可见，回到前台时立即同步，进入后台即停止；服务端不支持长轮询时退回每 20 秒同步。很多国内安卓设备没有 FCM，以后如需推送，考虑接入厂商推送 |
| 家长验证（孩子设备） | 使用系统锁屏密码（`KeyguardManager`）；设备没有设锁屏时给出提示 |

## 代码结构（`app/src/main/java/cn/littlebear/tutor/homework/`）

| 文件 | 内容 |
| --- | --- |
| `Api.kt` | 接口数据类型、错误文案、OkHttp 客户端（不跟随重定向）、服务器地址校验 |
| `Store.kt` | 本机唯一数据源：服务端数据缓存、`/v1/changes` 增量同步、离线提交队列（照片和它的缩略图一起排队，缩略图紧跟照片上传，失败不影响提交）、家长端操作、家长端同步后在后台预先下载等批改作业的缩略图和照片。逻辑和 iOS `Store.swift` 一一对应 |
| `Platform.kt` | 设备凭证用 Android Keystore 加密保存；照片处理（EXIF 旋转；作业照片长边 1400 像素、JPEG 质量 70，另做一张长边 480 像素的缩略图）；录音（AAC/MP4）与播放 |
| `Design.kt` | 配色、科目和评分样式、小熊、远程图片、批注叠加 |
| `HomeworkApp.kt` | 入口、首次连接、前台长轮询、错误提示 |
| `ParentScreens.kt` | 家长端：作业、录入（页面最上方先选“AI 整理”或“手动填写”，记住上次的选择；AI 整理后进核对页，手动填写在本页直接保存）、详情、修改、每天坚持、奖励规则、设置与配对 |
| `ParentReview.kt` | 批改：红笔、打勾、圈出、撤销，导出每页一张透明 PNG（与 iOS 互通），打分与评语 |
| `ChildScreens.kt` | 孩子端：选头像、今天、全部作业、拍照交作业（多页）、计时、录音、录像、看批改与订正、奖励时间、家长设置 |
| `RewardLock.kt` / `RewardLockSettings.kt` | 无障碍拦截、奖励时间放行、家长设置、暂停检测与锁定状态心跳；家长端显示失效提醒 |
| `Video.kt` | 录像作业：系统相机录像（最长 30 分钟）或从相册选，Media3 Transformer 压缩到 480p H.264（约 0.8 Mbps），存到相册 `Movies/小熊伴学`（给钉钉打卡用），排队上传；ExoPlayer 带设备凭证串流播放 |
| `DeskCamera.kt` | USB 外接摄像头：Camera2 找 `LENS_FACING_EXTERNAL`，页面内实时画面、点一下拍照、↻ 旋转（记住设置）、插拔即时更新；插着 USB 视频设备但系统没提供时给出提示；`rememberCameraGate` 在打开系统相机前先申请相机权限 |

调试版允许用 HTTP 连接本机、模拟器宿主（`10.0.2.2`）和家庭局域网地址，方便联调；正式版只允许 HTTPS。

## 自动化验证

| 命令 | 覆盖 |
| --- | --- |
| `./gradlew testDebugUnitTest lintDebug assembleDebug` | 单元测试（日期、地址校验、错误文案、离线队列与缓存、录入方式与作业保存）、手机和平板截图渲染、Lint、APK |
| `scripts/android-phase1-e2e.sh` | 启动临时服务端，用安卓数据层跑完整流程：家长连接 → 添加孩子 → 配对 → 录入三种作业 → 孩子离线拍照（排队，联网后补传）、计时、录音 → 家长批注批改并要求订正 → 订正后再批改 → 奖励入账与补差 → 使用奖励时间与每日上限 → 每天坚持上限 → 删除同步 → 重启读缓存 → 撤销设备 |

截图测试（`ScreenshotTest`）用 Robolectric 在 JVM 上渲染界面，输出到 `app/build/screenshots/`，包括手机竖屏和平板横屏下的家长端和孩子端。它能确认界面可以渲染、布局合理，但不能代替真机。

## 真机验收清单

状态：完整清单尚未逐项记录。2026-11-21/22 已在小米平板 9 Pro（HyperOS 4、Android 17）验证奖励锁定：闲置后拦截、设置页防关闭、连接部署服务端使用奖励时间及到时重新锁定，见[技术方案](tech-plan-phase1.md)。其余场景需补录结果；每次记录设备型号、Android 版本、App 版本和日期。

| 场景 | 操作与预期 |
| --- | --- |
| 连接 | 家长手机用服务器地址和家长密钥连接；生成配对码，孩子设备 10 分钟内配对成功 |
| 录入 | 默认“AI 整理”：粘贴含三科的群消息，AI 拆成三项；逐项修改后加入，孩子设备 1 秒左右看到。切到“手动填写”：不显示文本框，在本页填两项、加一张图片（默认附到第一项），直接加入；再次进入录入页仍是“手动填写” |
| 录像 | 家长录入一项“在线录像”；孩子录一段视频（或从相册选），看到压缩进度，提示“已存到相册”；在相册的“小熊伴学”里找得到；家长端能播放并打分。录超过 30 分钟时有提示 |
| 拍照提交 | 孩子拍 2 页、从相册选 1 页，横竖拍摄方向都正确，拍照页旋转后页面和已拍照片保留；暗的照片有提醒；家长端看得清楚 |
| 外接摄像头 | 插上 USB 摄像头打开“拍照交作业”：系统支持时页面里直接显示画面，点一下拍一页，↻ 转正后照片方向一致，插拔即时切换，切到后台再回来画面恢复；系统不支持时显示“系统不让应用直接用它”的提示，照常可用自带相机。首次点“拍第 1 页”会先申请相机权限 |
| 离线 | 孩子设备断网后提交，显示“等网络上传”；联网后自动补传，按设备时间判断是否按时 |
| 计时 | 计时未满不能打卡；切到后台计时暂停；满时长打卡后获得奖励 |
| 录音 | 首次录音时弹出麦克风权限；拒绝后有提示；录音能回放，家长端能播放 |
| 批改 | 红笔、打勾、圈出、撤销正常；双指缩放、拖动和还原大小后批注仍与照片对齐；多页作业可以逐页批注；孩子端看到的红笔和照片对齐 |
| 订正 | 要求订正后孩子重拍提交，家长再批改，奖励补上差额 |
| 跨平台 | 安卓家长批改 iPad 孩子的作业，以及 iPhone 家长批改安卓孩子的作业，批注都对齐 |
| 奖励时间 | 作业没交完、不在时段、超出每日上限时都不能用；倒计时结束有提示 |
| 奖励锁定回归 | 选定 App 在奖励期间可打开，到时重新拦截；验证“被暂停过”提示、多个孩子共用平板、重启后奖励到期；关闭服务后家长端能看到状态提醒（无后台推送） |
| 家长设置 | 孩子设备上点“家长”需要锁屏密码；断开后要重新配对 |
| 手机和平板 | 家长端和孩子端在手机竖屏、平板横竖屏都能用，按钮可点，键盘不遮挡提交按钮 |
| 覆盖安装 | 从 1.0.0-beta.1 覆盖安装后进入新的角色选择页，不崩溃 |

## 安卓应用内更新

家长手机打开“作业 → 设置 → 检查更新”。孩子手机或平板打开“家长设置”，完成设备验证后点“检查更新”。App 从已配对的服务器检查版本，有新版时自动下载并打开系统安装界面。首次使用按系统提示允许小熊伴学安装应用，返回后点“更新”。覆盖安装保留配对、作业缓存和本机设置。

已有 USB 安装的旧版本需要先用原签名覆盖安装一次带更新按钮的版本（1.1.0-alpha.2，versionCode 4）。可在原开发机构建后运行 `adb install -r app/build/outputs/apk/debug/app-debug.apk`。后续每次发布递增 `app/build.gradle.kts` 的 versionCode，并更新 versionName。沿用相同 applicationId 和签名密钥；如果旧包由另一台机器签名，需找回那台机器的密钥来构建。

**发布更新包**（在项目根目录执行）：

```sh
./gradlew assembleDebug
python3 scripts/publish-android-update.py app/build/outputs/apk/debug artifacts/android-updates
```

第一次发布时部署包含更新接口的网关代码并重启服务，把公网 HTTPS 的 `/android-updates/` 转发到同一网关。将生成目录中的散列名 APK 上传至网关的 `DATA_DIR/android-updates/`，传完后再替换 `latest.json`（可用 `ANDROID_UPDATE_DIR` 指定其他目录）。在网关所在机器构建时也可把发布脚本的第二个参数直接设成该目录。保留上一版 APK，供已取得旧清单的设备完成下载。后续替换包和清单即可生效。

发布后，用设备上配置的服务器地址打开 `/android-updates/latest.json`，核对 versionCode。设备仅下载更高版本，安装前校验文件大小、SHA-256、包名、包内版本和签名。若提示签名不匹配，换回原签名重新发布并重试。
