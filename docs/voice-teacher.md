# 小熊老师：语音老师技术方案

2026-11-13 起草。状态：第一版（P0 语音 + P1 白板的最小闭环）已实现。网页版用替身上游在 Chromium 里端到端跑通。2026-11-17 接真实服务实测，**火山流式识别、DeepSeek、火山语音合成（2.0，音色小何 `zh_female_xiaohe_uranus_bigtts`）全链路已通**：服务端收到“说完了”到第一段声音约 1.4–1.6 秒（识别定稿约 0.1 秒，DeepSeek 第一段约 0.9–1.2 秒，合成首包约 0.4 秒），孩子实际感受到的还要加上客户端判断说完的 0.8 秒。DeepSeek 默认先思考，关掉（`TEACHER_MODEL_THINKING=disabled`）后首段快约 1 秒，讲解质量未见变差。回复格式全部合规，白板 op 无被丢弃，要求直接给答案时仍引导。识别是用 macOS 合成语音测的，不是童声。**iPad Safari 未真机验收**，iPad 原生端后续已于 2026-11-18 真机跑通；童声、回声、打断及权限等完整场景仍需按下方清单记录结果。

## 目标

孩子在 iPad 上和“小熊老师”直接语音对话，体验对标 Claude 的语音模式：不用按住按钮，随时可以打断，有实时字幕。和普通语音助手的区别有两点：

1. **懂学情**：知道孩子的年级、最近的作业、完成状态和家长批改；以后还要知道各科进度和知识点掌握情况。
2. **图文并茂**：讲题时边说边在白板上画，数学用竖式、数轴、点子图、线段图、钟面等板书讲解。

## 链路

```
iPad                                   服务端 /v1/teacher                     上游
麦克风 ─ 系统回声消除 ─ VAD ─ 16k PCM ──▶ 流式 ASR 会话 ───────────────────▶ 火山 bigmodel_async
                                         ◀── 实时字幕 input.transcript.partial
                    input.audio.end ──▶ 定稿 ─▶ 提示词（规则 + 学情 + 历史 + 白板）─▶ DeepSeek（stream）
                                         ◀── 一行一段 JSON，逐段校验白板 op
白板 ◀─ segment {speech, board, await} ◀─┤
扬声器 ◀─ 24k PCM（4 字节头）◀───────────┴─ 每段送合成 ──────────────────────▶ 火山 TTS（HTTP Chunked）
```

- **打断**：小熊说话时孩子开口，客户端先暂停播放、把孩子的声音送去识别：识别出文字才发 `response.cancel`（服务端中止模型和合成请求）；识别结果是空的（咳嗽、关门、残余回声），小熊把被打断的那一段从头再说一遍，接着讲完。点一下小熊、或者打字，仍然立即打断。
- **验算**：小熊说出口或写在白板上的“算式等于结果”（如“三十五减十八等于十七”“5 × 6 = 30”）由服务端用代码重算（`server/src/verify.mjs`）。算错的那一段不发出去：服务端中止这次生成，告诉模型正确结果，让它从已经说过的地方接着讲；再错就以一句“我们一起慢慢算”的问句结束。引用或反问孩子的说法（“你说八加七等于十四，对吗？”）不算。提示词要求说结果时带上完整算式，便于核对。
- **等孩子回答**：一段标了 `await` 就到此为止，后面的不再生成和播放，避免模型自问自答。
- **只记孩子听到的**：回复生成得比播放快得多，孩子在第 2 段打断时，服务端往往已经生成完全部 4 段。所以取消时客户端报告“播到了第几段”（`played`），服务端把这次回复在对话历史里截到那一段，并把白板状态退回到孩子看到的样子。下一轮模型才知道自己实际讲到了哪里。
- **回声**：采音和播放走同一个音频上下文，开启回声消除（网页用浏览器的 `echoCancellation`，原生用同一个 `AVAudioEngine` 的 voice processing）；小熊说话期间开口检测的起始阈值再提高 8 dB，避免残余回声被当成插话。
- **同步**：一段的白板变化在这段开始播放时执行，这段音频播完才开始下一段，所以画面跟着声音走。没有 TTS 时，每段按字数停留（每字 0.22 秒，至少 1.5 秒）。
- **降级**：没配 ASR 只能打字；没配 TTS 只显示字幕；没配模型且 `VOICE_MOCK=true` 时回复固定的竖式演示。
- **音频中断**：来电、Siri、插拔耳机或切到后台会让系统停掉音频引擎。回到前台或中断结束后自动重建；麦克风恢复不了时退到只播放，并提示孩子改用打字。

## 协议 `littlebear.teacher.v1`

WebSocket `/v1/teacher`，凭证是一期的设备凭证（家长或孩子设备）。原生客户端用 `Authorization: Bearer <凭证>`；浏览器不能给 WebSocket 加请求头，改为提供两个子协议 `littlebear.teacher.v1, littlebear.token.<凭证>`，服务端只回选 `littlebear.teacher.v1`。

上行：

| 消息 | 说明 |
| --- | --- |
| `{"type":"session.start","childId":"…"}` | 必须先发；服务端加载该孩子的学情 |
| 二进制帧 | 孩子说话时的 PCM16LE、16 kHz、单声道音频，第一帧开启一次识别 |
| `{"type":"input.audio.end","turn":3}` / `input.audio.cancel` | 一句话说完 / 丢弃（说到一半静音、误触发） |
| `{"type":"input.text","text":"…","turn":4}` | 打字或点建议；正在听的那句话会被丢弃 |
| `{"type":"response.cancel","response":5,"played":2}` | 打断。带 `response` 时只取消那一次回复，避免迟到的取消误杀新回复；`played` 是已经开始播放的段数，服务端据此截断历史、回退白板 |

`turn` 是客户端自己递增的句子编号，服务端在定稿和 `response.start` 里原样带回。客户端只展示“最新一句、且之后没有被打断”的回复，其余的按编号取消。这样孩子连着说两句、或在识别还没出结果时点小熊打断，都不会播出过时的回复。

下行：

| 消息 | 说明 |
| --- | --- |
| `hello` → `session.ready {child, audio:{input, output}}` | `input`/`output` 为 null 表示没配 ASR/TTS |
| `input.transcript.partial / final {turn} / empty {turn}` | 实时字幕、定稿、没听到内容 |
| `input.speech_end` | 火山识别判定这句话说完了（`end_window_size` 800 毫秒）；客户端随即发 `input.audio.end`，和自己的开口检测谁先到算谁 |
| `response.start {response, turn}` | 一次回复开始；`response` 是递增编号 |
| `segment {response, index, speech, board, await, end?}` | 一段要说的话和白板 op；`await` 表示在等孩子回答；`end` 表示孩子要走了，这是道别的最后一段，播完客户端自己结束对话、回到首页 |
| 二进制帧 | 前 4 字节：uint16 回复编号、uint16 段号（大端），后面是 PCM16LE（每帧都是完整的 16 位采样），采样率见 `audio.output` |
| `segment.audio.done {response, index, audio}` | 这段音频发完；`audio:false` 表示没有声音 |
| `response.done` / `response.cancelled` / `error {code}` | |

## 白板 DSL

模型不画坐标，只放语义化元素，客户端负责排版和动画（`server/src/board.mjs` 校验；网页 `web/teacher/board.mjs`、原生 `ipad/…/Teacher/TeacherBoard.swift` 渲染）。竖式的结果、进位和退位由客户端自己计算，不用模型给的数。

操作：`clear`、`add {el}`、`update {id, set}`、`remove {id}`。服务端把 `update` 合并成完整元素再下发，所以客户端收到的 `add`/`update` 都是整个元素。最多 12 个元素，无效 op 直接丢弃，不影响同段的其他内容。

| 元素 | 字段 | 用途 |
| --- | --- | --- |
| `text` | `text`，`style`: title / body / answer / hint | 题目、结论、提示 |
| `vertical` | `a`、`b`、`operator`（+ − ×）、`reveal`（从个位起写出几位）、`focus`（高亮哪一位） | 竖式，进位和退位标记自动画 |
| `number_line` | `from`、`to`、`step`、`marks`、`jumps [{from,to,label}]` | 数轴、跳数 |
| `dots` | `groups`、`per`、`highlight`、`label` | 乘法、除法、分组 |
| `bar` | `rows [{label, parts [{value, label}]}]`、`total` | 线段图，未知量 `value: null` 画成虚线 |
| `clock` | `hour`、`minute`、`label` | 认识时间 |
| `pinyin` | `title`、`lines [{text, pinyin}]`（最多 8 行；每个汉字一个带声调的音节，个数必须对上，标点不标） | 古诗、课文句子：字上标拼音 |
| `hanzi` | `char`（一个汉字）、`pinyin`、`parts`（部件，≤4）、`words`（组词，≤4）、`note` | 生字卡：田字格里写大字，形近字比较时每字一张 |
| `word` | `word`（英文）、`syllables`、`meaning`、`example` | 英语单词卡 |

讲题时用 `update` 一步步推进，例如先只列竖式，问孩子个位得几，再 `{"op":"update","id":"v1","set":{"reveal":1,"focus":0}}` 写出个位。

## 学情

放进系统提示词的有两部分：孩子姓名年级、最近 7 天到明天的作业（科目、内容、状态、交作业日期、家长评分和评语）；以及小熊自己记的**学情卡片**。

**学情卡片（对话记忆，2026-11-18 实现）**：每次对话结束（连接关闭）后，服务端把旧卡片和这次孩子实际听到的对话交给模型，重写成不超过 8 条、300 字的笔记（`server/src/memory.mjs`），存在 `teacher_memory` 表，每个孩子一张。下次对话放进提示词，要求小熊像记得这个孩子的老师那样自然接上，不念给孩子听。
- 只记对教学有用的：学了什么、哪些会了、卡在哪（具体到错法）、什么讲法有效、下次接着做什么。不记住址、学校、家人等个人信息，不记原话，不贴“粗心”之类的标签。
- **只保存这张卡片，录音和对话原文都不保存**；对话原文只在这次连接的内存里，写完卡片就丢掉。
- 少于两句的对话不写；模型说没什么可记、返回空或者出错时，保留旧卡片。
- 家长在家长端“设置 → 孩子 → 小熊老师的记忆”里能看到卡片，并能清除（`GET/DELETE /v1/children/:id/teacher-memory`，只有家长设备能调用）；删除孩子时一起删除。

用真实模型试的效果（2026-11-18）：一次讲 38+27（个位先错成 5，提示后改对）加背《静夜思》的对话，卡片记下“个位满十起初直接写 5，提示后能改对，进位概念需再巩固”“已能完整背《静夜思》”“下次练几道两位数进位加法”；孩子顺口说的住址和学校没有记。隔天一次全对的 46+38，卡片改成“进位加法已掌握，不再需要提醒”。

后续（P2）：

- `subject_progress`：教材版本和当前单元，先由家长设置，再尝试从作业内容推断。
- `skill_mastery`：知识点掌握度，来源是批改结果、讲题时孩子的回答。
- `learning_events` 流水和每次对话的摘要，作为小熊的长期记忆（“上次那道进位加法会了吗？”）。
- 数据模型初稿（参考 Duet 方案）：`SkillState`（孩子 × 知识点：掌握度、练习次数、下次复习时间）、`Attempt`（一次作答：知识点、对错、用了几次提示、耗时、错误类型，来源是作业批改或讲题时的回答）、`Misconception`（错误类型，相关题做对后关闭）。掌握度先用 BKT（简单，能给家长讲清楚），复习时间用 FSRS。
- 数据变多后改为工具调用按需查询，不再整段塞进提示词。

## 教学和安全

- 作业题引导式：一次只推进一步，问完等孩子回答，不直接说答案；好奇心问题可以直接讲。
- 只聊学习，不索取个人信息；学情、白板和孩子的话都按数据处理，不能改变规则。
- 服务端不保存音频和对话原文，只保存学情卡片（见上）。使用时长限制放到后续，和一期的奖励时间共用一套。
- 孩子说再见、不想学了或要去做别的事：小熊道别一两句，最后一段带 `end`，播完对话自动结束，不再提问或挽留。
- 调试时可以设 `TEACHER_LOG=1`，服务端会打印每一轮识别到的话、小熊说的话和画的东西；它会把孩子的话打到日志里，平时不要开。
- 对外上线前确认国内合规（待法务确认）：《个人信息保护法》把不满 14 岁儿童的个人信息列为敏感个人信息，需要监护人同意并有专门的处理规则；《未成年人网络保护条例》；面向公众的生成式 AI 服务的备案要求。

## 评测集

2026-11-17（deepseek-flash，关思考）：25 题里 23 题没有问题，第一段中位 0.88 秒、P90 1.15 秒，验算 0 次拦截（这些题模型都算对了）。剩下两条是一段超过 50 字、一个白板操作被丢弃。跑评测时发现并修了三处：模型把文字样式写成元素类型（`"type":"title"`）、点子图 `highlight:-1`、一次回复里提问后又自问自答。

2. **iPad 原生**（孩子端首页右上角“小熊老师”）和 **iPad Safari**（`/teacher/`）各试一次：
   - 说“三十八加二十七等于多少”，从说完到小熊开口要等多久（电脑上测的是 1.4–1.6 秒，再加 0.8 秒判断说完）。
   - 小熊说话时咳嗽一声或拍一下桌子：应该停一下，然后把那句话重说一遍接着讲，而不是丢掉。
   - 小熊说话时正常插话：应该停下来回答新的问题。
   - 不戴耳机时，小熊会不会被自己的声音打断。
   - 孩子本人说话的识别准不准，数学说法是否转成了数字。
   - 小何的音色和语速是否合适（不合适改 `VOLC_TTS_SPEAKER`、`VOLC_TTS_SPEECH_RATE`）。
3. **麦克风权限被拒绝时**：原生端应该退到打字并提示，不崩溃（模拟器里发现并修了一个崩溃：没有麦克风时仍然申请录音模式，音频服务初始化卡死）。

已知的取舍：语义化的说完判断（如 Pipecat Smart Turn）还没加；孩子说话中间停顿超过 0.8 秒会被当成说完。真机上如果常被切成两句，先调 `endAfterMs`，不够再加。

## 参考

[K12 数字老师 Agent：开源模型选型调研](https://claude.ai/artifact/Rjd6Sgm5jMS7waDGki23Xz)（2026-11-13，数字未逐页复核）。和本方案一致的部分：级联语音、say/draw 结构化白板、服务端校验、按段同步、不让模型给坐标。采纳情况：

- **验算**（已实现，见“链路”）：二三年级不需要 SymPy，服务端从说的话和白板文字里找出算式重算。
- **拍题**：题图直接交给多模态模型，不先 OCR。
- **模型升级路径**：先用 API，量大后评估单卡自部署。大脑走 OpenAI 兼容接口，换模型只改环境变量。

“Personal Study Agent: Architecture”（Claude Duet 对话，2026-11-17，未存进仓库）。这份是按全球、全年龄段设计的通用 tutor，它自己也建议国内走级联加开源模型，和本方案一致。采纳的部分已经写进上文：验算、学情卡片、P2 数据模型、语义化说完判断、时长控制。不采纳的部分：
- 端到端实时语音模型作为默认链路（国内用不了）。
- 用 LaTeX `write_step`、几何和函数图像（面向中学以上；让模型写数字反而容易错，竖式结果仍由客户端计算）。
- 它推荐的技术栈：React Native、LiveKit/WebRTC、分地区 Postgres、Temporal（和现有的原生客户端加 Node 服务端不匹配）。
- 测验工具和学习计划器（范围大一圈，至少排在 P2 之后；一期作业管理已经承担了“每天做什么”）。
- 它的合规表（COPPA、GDPR 等，不覆盖国内）。
